🔐 tunnel-client 跨平台隧道客户端开发方案

Android & Windows · 支持 SSTP / L2TP/IPsec / PPTP · 对接 MikroTik RouterOS

1. 方案概述与协议策略

本方案面向 Android 与 Windows 双平台客户端，目标服务器为 MikroTik RouterOS。核心设计原则：共享协议逻辑，分离平台适配层，确保证书验证策略、端口配置、连接行为在两个平台上完全一致。

📌 关于 SSTP 证书验证与端口
• MikroTik 的 SSTP 服务端支持自定义 port（默认 443），客户端必须允许配置端口。
• 证书验证策略建议：默认开启验证（导入 CA 或使用商业证书），并提供“忽略证书验证”高级选项并附风险提示。
• 自定义端口时，SSTP 穿透性可能下降，UI 可做轻量提示。

1.1 协议优先级

协议优先级理由端口
SSTP P0 · 首要 基于 TLS/443，穿透防火墙强；MikroTik 配置简单；可自定义端口；双平台行为可控 默认 443，可配置
L2TP/IPsec P1 MikroTik 常用协议，但 IKE 协商复杂；可借助 strongSwan 等库降低复杂度 UDP 1701（IPsec NAT-T 可自定义）
PPTP P2 · 兼容 官方已标注“不推荐”，安全缺陷明显；仅用于旧设备兼容，UI 需标注风险 TCP 1723

2. 整体架构设计

推荐采用 C/C++ 共享核心 + 平台外壳 的架构。两个平台的最大差异在于虚拟网卡和生命周期管理，协议协商与加密逻辑完全共享。

📦 共享核心层优势

  • SSTP 本质是“TLS 上的 PPP”，L2TP 是“UDP 上的 PPP”。两者最终汇聚到同一个 PPP 状态机。
  • 用 C 实现一次 PPP（LCP / MS-CHAPv2 / IPCP），Android 与 Windows 共用，保证认证行为完全一致。
  • 证书验证、端口配置、加密套件协商统一，避免平台差异。

⚙️ 平台适配层职责

  • Android：VpnService 获取 TUN fd，JNI 传入核心层；前台服务保活；Always-On 支持。
  • Windows：Wintun 驱动创建虚拟网卡；服务模式运行；路由表配置；证书存储管理（自实现路线无需修改系统信任库）。

3. Android 客户端方案

3.1 VpnService 集成要点

  • 继承 VpnService，在 AndroidManifest.xml 声明 BIND_VPN_SERVICE 权限。
  • 调用 VpnService.prepare() 获取用户授权。
  • 通过 VpnService.Builder 配置 TUN IP、路由、DNS。支持全局路由 0.0.0.0/0 或分流网段。
  • establish() 获得 ParcelFileDescriptor，将其 fd 传递至 Native 层。
  • Android 10+ 后台限制：必须调用 startForeground() 并绑定不可关闭的通知。

3.2 协议实现路径

🔒 SSTP（首要）

  • OpenSSL 建立 TLS 连接，目标地址为 配置中的服务器地址:端口（默认 443）。
  • 证书验证：默认系统 CA + 用户导入的 CA；高级选项可设为“不验证”。
  • TLS 建立后发送 SSTP 控制报文，启动 PPP 协商。
  • MikroTik SSTP 通常要求 MS-CHAPv2 认证。

🛡️ L2TP/IPsec

  • 集成 strongSwan Android 库处理 IKEv1 协商（PSK 认证）。
  • IPsec 隧道建立后，通过 UDP 1701 发送 L2TP 控制包。
  • 随后运行 PPP 协商（与 SSTP 共用 PPP 栈）。
  • MikroTik 需配置 use-ipsec=yes 及预共享密钥。

3.3 后台保活与 Always-On

利用 Android 7.0+ 的 Always-On VPN 特性：用户在系统设置中开启后，VPN 服务会在设备启动时自动启动，并在断开时显示不可关闭的通知。应用层配合 ConnectivityManager.NetworkCallback 监听网络切换，触发重连。

4. Windows 客户端方案

⚠️ 关于系统 RAS 路线
Windows 原生 SSTP 客户端强制验证服务器证书，无法在代码中跳过。若 MikroTik 使用自签名证书，必须通过安装程序导入到“受信任的根证书颁发机构”存储。且 RAS 无法精细控制 PPP 参数。
本方案推荐：自实现协议栈 + Wintun 驱动，与 Android 保持行为一致。

4.1 推荐路线：自实现协议栈 + Wintun

  • 使用 Wintun（WireGuard 项目开源 TUN 驱动）创建虚拟网卡，性能好、许可证宽松。
  • 共享核心层负责 PPP / SSTP / L2TP 协议，将 IP 包封装后发往 MikroTik。
  • 证书验证策略与 Android 完全一致：默认验证，可选忽略。
  • 路由配置通过 Windows API（CreateIpForwardEntry 或 netsh）将目标网段指向 TUN 接口网关。
  • 建议将 VPN 连接逻辑放在 Windows 服务中运行，支持开机自动连接、网络切换恢复；UI 通过命名管道或 gRPC 与服务通信。

4.2 备选路线：调用系统 RAS API（快速但受限）

如果项目时间紧迫且不要求证书忽略功能，可使用 RasSetEntryProperties + RasDial 创建和拨号 VPN 连接。支持 SSTP / L2TP / PPTP 类型，可传入服务器地址、用户名、密码、PSK。

局限：SSTP 证书验证由系统控制，自签名证书必须导入信任库；无法自定义 PPP 协商参数。仅建议在“商业 CA 证书 + 无特殊协议需求”场景下使用。

7. 关键风险与应对

风险应对措施
SSTP 证书验证策略不一致坚持自实现协议栈，双平台使用同一套 C 代码做证书验证，UI 开关同步
MikroTik 加密算法协商失败在测试环境穷举 MikroTik 支持的加密套件（AES-128/256 等），核心层记录协商日志便于排查
自定义端口影响穿透性UI 端口输入框旁提示“非 443 端口可能降低防火墙穿透性”
Android 后台被杀Always-On + 前台服务 + 厂商白名单引导（国产 ROM 需额外适配）
Windows RAS 证书不可控若选 RAS 路线，安装程序处理 CA 导入；否则走自实现路线
PPTP 被运营商封锁 GREUI 明确提示：PPTP 在移动网络下可能无法连接，建议使用 SSTP

8. 方案修订说明（相对上一版）

  • 明确 SSTP 端口可配置：MikroTik 服务端支持自定义 port，客户端配置界面必须允许修改，默认 443。
  • 核心层连接参数化：TLS 连接目标使用配置中的端口，不硬编码。
  • Windows 自实现路线：同样使用共享核心层的端口参数，无额外适配。
  • UI 提示：非 443 端口可能影响穿透性，在端口输入框旁添加轻量提示。
  • 证书验证策略：默认开启验证，提供“忽略证书验证”高级选项并附风险提示，跨平台行为一致。
✅ 方案核心决策
用 C/C++ 实现共享的 PPP + SSTP 协议栈，两个平台各自负责 TUN 网卡和连接生命周期。这保证证书验证策略完全可控且双平台一致，同时避免 Windows RAS 路线的证书不可绕过问题。SSTP 作为首要协议，L2TP/IPsec 次之，PPTP 仅作兼容并标注风险。端口自定义作为标准配置项贯穿所有协议。
